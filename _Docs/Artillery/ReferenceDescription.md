# Task 7. Справочные данные для расчета ВР и ДМК (Таблица 2, Таблица 3)

ER-диаграмма: `ReferenceERDiagram.pgerd`. Скрипт: `Reference_tables.sql` (PL/pgSQL, повторяемый).

## Идея хранения
Все таблицы поправок хранятся в одной структуре «заголовок + строки»:
- **тип таблицы** описывает таблицу и ее заголовок столбцов (массив `header_values`);
- **строка таблицы** - одна запись: стандартная высота + массив значений `row_values`. Значение `row_values[i]` относится к столбцу `header_values[i]`.

Так для всех таблиц хватает трех справочных структур, а новая таблица поправок добавляется данными, а не новым DDL.

## Что хранится и где

| Таблица | Что хранит |
|---|---|
| `standartnye_vysoty` | Стандартные высоты Y: 200, 400, 800, 1200, 1600, 2000, 2400, 3000, 4000 м (строки таблиц 2 и 3) |
| `tipy_tablic_popravok` | Справочник таблиц: код, название, оборудование, заголовок столбцов, родитель |
| `tablicy_popravok` | Значения строк всех таблиц: (тип таблицы, высота) → массив значений |
| `konstanty` (существующая) | Пороги алгоритма: V0 < 3 м/с (ДМК), Дг < 40 м (ВР), границы высот 200 и 4000 м |

### Типы таблиц (`tipy_tablic_popravok`)

| Код | Что это | Оборудование | Заголовок (столбцы) |
|---|---|---|---|
| `TBL2` | Таблица 2 (общий родитель) | ДМК и ВР (NULL) | Δτ0: 1..10, 20, 30, 40, 50 |
| `TBL2_POS` | Положительные отклонения (знаменатель) | наследует | у родителя; значений 12 (нет столбцов 40 и 50) |
| `TBL2_NEG` | Отрицательные отклонения (числитель) | наследует | у родителя; значений 14 |
| `TBL3_SPEED`, `TBL3_DIR` | Таблица 3: скорость / направление (родители) | - | - |
| `TBL3_SPEED_VR` | Скорость среднего ветра, ВР | ВР | Дг: 40..150 м (шаг 10) |
| `TBL3_DIR_VR` | Приращение направления, ВР | ВР | нет: одно значение на строку |
| `TBL3_SPEED_DMK` | Скорость среднего ветра, ДМК | ДМК | V0: 3..15 м/с |
| `TBL3_DIR_DMK` | Приращение направления, ДМК | ДМК | нет: одно значение на строку |

Таблицы 2 для ДМК и ВР на картинках 13 и 15 одинаковы, поэтому хранятся один раз без привязки к оборудованию. Значения Таблицы 2 хранятся со знаком, поэтому запись «числитель/знаменатель» заменена разбиением на `TBL2_NEG` и `TBL2_POS`.

Приращение направления хранится в больших делениях угломера: `1-00` → 1, `4-00` → 4, `0-00` → 0.

## Связи
- `tablicy_popravok` → `tipy_tablic_popravok` (N:1), → `standartnye_vysoty` (N:1); пара (тип, высота) уникальна;
- `tipy_tablic_popravok` → `tipy_oborudovaniya` (N:1, NULL для общих таблиц);
- `tipy_tablic_popravok` → `tipy_tablic_popravok` (родитель, N:1).

Все таблицы имеют `id` и `uniq_code`, ограничения и комментарии, как в остальной схеме. Расчетные функции ищут таблицу по символьному коду `code`, а не по `id`.

## Контроль данных
В конце скрипта выполняется проверка: число значений в строке не превышает число столбцов заголовка (заголовок берется у типа или у родителя), а при отсутствии заголовка в строке ровно одно значение. Проверочный запрос выводит Таблицу 3 для ДМК в развернутом виде (высота, V0, скорость, приращение направления).
