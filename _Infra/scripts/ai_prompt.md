Сформируй DML-скрипт строго в синтаксисе ANSI SQL-92. Скрипт должен быть перезапускаемым: повторный запуск не создаёт дублей и не падает. Используй только INSERT и DELETE, без CREATE / ALTER / DROP. Комментарии пиши на русском.

Предметная область: метеоизмерения для артиллерии. Измерения проводятся двумя типами оборудования: ДМК (id=1, десантный метео комплекс) и ВР (id=2, ветровое ружьё). Пачка (pachki) — один сеанс измерений одного пользователя; created_date — дата измерения.

СТРУКТУРА (таблицы уже созданы):

dolzhnosti(id, uniq_code, name)
tipy_oborudovaniya(id, uniq_code, name)
polzovateli(id, uniq_code, full_name, dolzhnost_id)
pachki(id INTEGER, uniq_code VARCHAR(20) UNIQUE, tip_oborudovaniya_id, polzovatel_id, quantity INTEGER CHECK (quantity > 0), created_date DATE)
parametry(id INTEGER, uniq_code VARCHAR(20) UNIQUE, tip_oborudovaniya_id, tip_parametra_id, value VARCHAR(100), pachka_id INTEGER)
-- одна строка = одно измеренное значение одного параметра в одной пачке
tipy_parametrov(id, edinica_izmereniya_id, name)
edinicy_izmereniya(id, bazovaya_edinica_id, short_name, name)
bazovye_edinicy_izmereniya(id, name)

УЖЕ ЗАПОЛНЕННЫЕ СПРАВОЧНИКИ (не изменять, только использовать id):

dolzhnosti: 1 = Рядовой, 2 = Лейтенант
tipy_oborudovaniya: 1 = ДМК, 2 = ВР
polzovateli (уже есть): id 1 (Иванов Иван Иванович), 2 (Петров Пётр Петрович), 3 (Сидорова Анна Сергеевна)
tipy_parametrov (id — название — единица — допустимые значения):
1 Высота — метр — целое число, может быть отрицательным
2 Температура — градус Цельсия — от -58 до 58, ровно один знак после запятой
3 Давление — мм рт. ст. — целое, от 500 до 900
4 Направление ветра — деление угломера — целое, от 0 до 59
5 Скорость ветра — м/с — целое, от 0 до 15
6 Дальность сноса пуль — метр — целое, от 0 до 150

НАБОР ПАРАМЕТРОВ ПО ОБОРУДОВАНИЮ (в каждой пачке ровно 5 параметров):

ДМК: типы 1, 2, 3, 4, 5
ВР: типы 1, 2, 3, 4, 6

ТРЕБОВАНИЯ К ДАННЫМ:

В начале скрипта удали данные в таком порядке: сначала из parametry, затем из pachki, затем из polzovateli только строки с id > 3. Справочники и пользователей с id 1..3 не трогай.
Добавь 3 новых пользователей (id 4, 5, 6; uniq_code 'USR-004'..'USR-006'):
Имена придумай сам.
Поле dolzhnost_id для них — 1 или 2 (на твой выбор).
Создай 18 пачек (id 1..18, uniq_code 'PCH-001'..'PCH-018') за сентябрь 2026, по одной на каждый день (DATE '2026-09-01' ... DATE '2026-09-18').
У каждого из шести пользователей (id 1..6) ровно по 3 пачки.
Оборудование не чередуй, но распредели ровно 9 пачек ДМК и 9 пачек ВР. У каждого пользователя должны быть пачки обоих типов оборудования.
В pachki.quantity для каждой пачки проставь 5 (количество параметров в пачке).
Для каждой пачки создай 5 строк в parametry согласно набору параметров её оборудования. Поле tip_oborudovaniya_id в parametry должно совпадать с оборудованием пачки, pachka_id — с id пачки.
id в parametry — сквозные 1..90, uniq_code — 'PAR-001'..'PAR-090'.
Поле value — строка, десятичный разделитель — точка (например '12.5', '748'). Для целочисленных параметров — без дробной части ('748', а не '748.0'), температура — всегда с одним знаком после запятой ('12.0', '-3.5').
Значения реалистичные, строго в допустимых диапазонах, не одинаковые во всех пачках.
Формат вставки, например:
INSERT INTO polzovateli (id, uniq_code, full_name, dolzhnost_id) VALUES (4, 'USR-004', 'Кузнецов Алексей Николаевич', 1);
INSERT INTO pachki (id, uniq_code, tip_oborudovaniya_id, polzovatel_id, quantity, created_date) VALUES (1, 'PCH-001', 1, 1, 5, DATE '2026-09-01');
